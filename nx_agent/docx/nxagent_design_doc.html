What does the market actually want?

Real pain points from GitHub issues, Reddit threads, and dev forums across major frameworks:

Pain 1

Debuggability

Developers hate black-box agents. They want to see exactly what was called, with what args, and what came back.

Pain 2

Vendor lock-in

Switching from OpenAI to Anthropic should be one line change. Most frameworks make it a nightmare.

Pain 3

Over-engineering

LangChain's LCEL, Chains, Callbacks, Runnables — beginners give up. Simple things should be simple.

Pain 4

No memory story

Short-term and long-term memory are bolted on as afterthoughts in most frameworks.

Pain 5

Hard to test

Agents that depend on live LLMs can't be unit tested. Swappable backends make mocking trivial.

Pain 6

No production path

Easy to prototype, impossible to deploy. Retries, timeouts, error handling are missing.

What is the "agentic loop"?

This is the heart of every agent framework. Understanding this loop is the most important thing you'll learn:

1

Receive task + context

The agent gets a task string and any context from previous agents. It builds a system prompt from its role, goal, long-term memory, and available tools.

2

Call the LLM

Send the system prompt + task to the LLM backend. The LLM sees the list of available tools and decides: answer directly, or call a tool first.

3

Parse the response

Did the LLM return a TOOL_CALL:name:{args} directive? If yes — execute the tool. If no — this is the final answer. Go to step 5.

4

Execute tool → feed result back

Run the Python function. Record the result in the trace. Append the tool result to the conversation and loop back to step 2.

5

Return StepResult

Package the final answer, all tool calls, timing, and metadata into a StepResult. Update short-term memory. Return to the Workflow.

Key design rule: layers only talk down

The Workflow calls Agents. Agents call the LLM Backend and Tool Executor. The Tool Executor calls Python functions. Nothing calls upward.

Good ✓

Workflow → Agent → LLM
Agent → ToolExecutor → fn()
Tracer records everything passively

Bad ✗

Tool calling back into Agent
LLM Backend talking to Router
Memory modifying Workflow state

Section 3

Every module, explained

Here is every file you need to build, what it does, and what decisions matter inside it.

tool.py — The @tool decorator

Job: Turn a normal Python function into something an LLM can use. It reads the type hints and docstring to build a JSON schema automatically.

@tool
def web_search(query: str) -> str:
    """Search the web for current information."""
    return requests.get(url).text

# What the decorator builds automatically:
# { "name": "web_search",
#   "description": "Search the web for current information.",
#   "parameters": { "query": {"type": "string"} } }

Key decision: The function must remain callable as normal Python. The decorator only adds a .schema attribute — it never wraps the function in a way that breaks normal use.

agent.py — The Agent class

Job: One focused worker. It has a role, a goal, and optional tools. It runs the agentic loop and returns a StepResult.

— max_iterations: A safety cap on the tool loop. Without this, a confused LLM loops forever.
— Backend-agnostic: The Agent calls llm_backend(system, user, tools) → str. It never imports OpenAI or Anthropic directly.
— Tool validation on init: Fail loudly at construction time. Never fail silently at runtime.

memory.py — Two-tier memory

Job: Every agent has a Memory object with two tiers.

ShortTermMemory

A deque with maxlen=20. Stores recent turns. Automatically evicts old entries. Builds conversation context for the LLM.

LongTermMemory

A dict of facts. Always injected into the system prompt. Survives context window resets. Never evicted.

router.py — Routing strategies

Job: Decide which agent runs next and in what order.

backends.py — Pluggable LLMs

Job: Every backend is just a function: fn(system, user, tools) → str. Swapping LLMs is one line.

openai_backend()
Uses function_calling. Maps tools to OpenAI format. Handles tool_calls in response.
anthropic_backend()
Uses Claude's tool_use blocks. Maps to Anthropic schema.
Custom fn
Any callable that returns a string. Use for local models or mocking in tests.
Section 4

How to shine

The gap between "another agent framework" and "the one developers choose" is in these five bets.

Bet 1 — Observability as a first-class citizen

LangChain added LangSmith as a paid product. You should make full trace visibility free and built-in. Every framework user's first question when something breaks is "what actually happened?" Answer it before they ask.

To build: OpenTelemetry spans per step. Export to Jaeger/Grafana. A result.pretty() that prints a full tree. A result.to_json() for logging pipelines.

Bet 2 — Zero-friction tool creation

Add a tool library of 30+ pre-built tools (web_search, code_executor, file_reader, calculator, etc.) that work out of the box. Developers love copy-pasting a working example.

To build: nx_agent.tools.web, nx_agent.tools.code, nx_agent.tools.files. Each module is optional. Tool docs auto-generate from schema.

Bet 3 — Streaming support

Every serious production app streams tokens. LangChain's streaming is notoriously broken. Being the framework that "just works" with streaming is a massive differentiator.

To build: agent.stream(task) that yields tokens as they arrive. workflow.stream(task) that yields per-agent chunks with step boundaries.

Bet 4 — Retry and resilience built-in

LLM APIs have rate limits. Tools fail. Networks hiccup. Most frameworks leave all of this to the user. Ship a retry engine with exponential backoff and graceful degradation.

To build: @tool(retries=3, backoff=2.0). An Agent-level retry_policy. A circuit breaker that stops hammering a failing API.

Bet 5 — First-class testing utilities

Nobody else ships a proper mock LLM backend for testing. Being the framework where agent workflows are fully unit-testable will win enterprise adoption.

To build: MockBackend that replays recorded conversations. assert_tool_called(result, "web_search"). pytest fixtures.

Build in this exact order. Each phase produces something shippable. Never jump ahead.

Phase 1 — The core (weeks 1–3)

Ship this
✓ @tool decorator with auto-schema
✓ Agent with agentic loop
✓ Workflow + Router (sequential/parallel)
✓ Memory (short + long term)
✓ WorkflowResult + StepResult
✓ OpenAI + Anthropic backends
✓ 25 unit tests passing

Phase 2 — Resilience (weeks 4–6)

High priority
□ Retry engine with exponential backoff for tools and LLM calls
□ Timeout per agent and per tool
□ @tool(retries=3, timeout=10) decorator params
□ Graceful degradation: return partial results if one agent fails
□ Rate limit detection and automatic backoff
□ Structured error hierarchy: AgentError, ToolTimeoutError, etc.

Phase 3 — Streaming (weeks 7–9)

High priority
□ agent.stream(task) → AsyncGenerator[str, None]
□ workflow.stream(task) with step boundary events
□ StreamEvent types: token, tool_start, tool_end, step_start, step_end
□ Both OpenAI and Anthropic streaming backends
□ Streaming works through tool calls (not just final output)

Phase 4 — Observability (weeks 10–12)

Important
□ OpenTelemetry integration: one span per step, one span per tool call
□ Structured JSON logging via standard library
□ result.to_json() for log pipelines
□ Token usage tracking per step and per workflow

Section 6

The production checklist

Every item here separates a toy from a framework developers trust in production.

M Must have D Differentiator W Wow factor

Correctness

M
Agentic loop has a safety cap. max_iterations stops infinite loops. Configurable per-agent.
M
Tools validated at construction time. Passing a non-@tool function to Agent raises immediately with a clear message.
M
Tool errors captured, not raised. A tool throwing an exception becomes a ToolCall.error — the agent continues.
M
Thread-safe parallel execution. parallel router uses ThreadPoolExecutor correctly. No shared mutable state.

Observability

D
Every tool call is recorded with inputs, outputs, errors, and duration. Zero black boxes.
D
WorkflowResult is serializable. result.to_dict() and result.to_json() work without external libraries.
W
OpenTelemetry spans exported automatically. Drop-in support for Jaeger, Grafana, Datadog — zero config if OTel SDK is installed.
W
Token usage and cost tracked per step. result.steps[0].tokens_used, result.total_cost_usd.

Developer experience

M
Zero hard dependencies in core. pip install nx-agent installs nothing else. All LLM libs are optional extras.
M
Type hints everywhere. Every public function has full type annotations. mypy passes with no errors.
D
MockBackend for testing. Agent tests run without internet, without API keys, with deterministic results.
D
Swapping LLMs is one line. Change llm_backend=anthropic_backend() to openai_backend() — nothing else changes.
W
Error messages guide, not just inform. AgentError tells you which agent, what task, what went wrong, and what to try next.

Things to avoid

✗
Never call layers above you. A Tool must never call back into Agent. An Agent must never modify Workflow state.
✗
Never import LLM libraries at the top level. Only import inside backend factory functions. Core stays dependency-free.
✗
Never silently swallow exceptions. Every error must be re-raised with context, or recorded in the trace with full details.
✗
Never make global state. No module-level LLM clients, no singleton registries that break test isolation.
